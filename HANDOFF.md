## 1. What the product is

A senior-friendly phone directory that replaces Googling for customer-service numbers.
Scammers buy "Sponsored" search ads that impersonate support lines (tech-support fraud
cost seniors $159M+/yr; FTC estimates total elder fraud at $10–81B/yr). The app shows 50
of the most-impersonated brands as big colored text buttons. Tapping one shows a 3-second
safety warning, then opens the native dialer. It works fully offline after activation.

**Business model (Web Checkout First / Login-Only):** a caregiver clicks an influencer
link, subscribes on the **web** via Stripe ($4.99/mo or $29.99/yr), and gets a
**6-digit activation code**. The mobile apps only accept that code and contain **no**
pricing or purchase language (App Store guideline 3.1.3(b), the Netflix pattern), so
there's no 15–30% store fee.

- **Free tier:** 50 brands + 3 caregiver-added contacts. **Premium:** unlimited contacts.
- **v1 additions agreed with the user:** a "Call My Person" panic button (dials the
  caregiver, never 911), and contacts the caregiver pre-loads at signup so the app isn't
  empty on first open.

## 3. Architecture and key flows

**Activation (the core security contract).** The app calls `GET /v1/signing-key`, then
`GET /v1/activate/{code}`, verifies the Ed25519 signature, and caches the result. After
that it runs offline. The signed string is:

```
account_id | tier | issued_at | sha256(contacts_json)
```

`contacts_json` is Python's `json.dumps({"emergency":…, "custom":[…]}, sort_keys=True,
separators=(",",":"), ensure_ascii=True)`. **The backend, iOS and Android must produce this
string byte for byte.** Each platform has a test pinned to the same backend-generated
golden value. QA independently rebuilt it (including quotes, `&` and accented
characters), confirmed real signatures verify, and confirmed a tampered contact fails.
**If you change the format, update all three platforms and their tests together.**

**Backend endpoints**
- App: `GET /v1/brands`, `GET /v1/signing-key`, `GET /v1/activate/{code}`
- Funnel: `POST /v1/checkout/session`, `GET /v1/checkout/result`, `POST /v1/webhooks/stripe`
- Caregiver (auth via `X-API-Key` header): `GET/PUT /v1/account`,
  `GET/PUT /v1/account/emergency-contact`, `GET/POST/DELETE /v1/account/contacts`
- Dev only: `POST /v1/dev/accounts` (switched off in production and once Stripe is configured)

**Online-only brands.** 10 brands have no phone support at all: Roku, Hulu, Max,
Paramount+, Peacock, Spotify, Google, Facebook, Instagram, Zelle. Their `phone` is `null`.
The app shows "this company has no support line; anyone giving you one is a scammer"
instead of dialing.

## 4. Deliberate decisions (don't undo without reason)

1. **Verification statuses mean different things.** `web_corroborated` (37 entries) means
   cross-checked by web research. It is **not** `verified` (currently 0). Only a person
   checking the official page earns `verified`. Never market the directory as
   "verified" or "un-spoofable" until all 50 are verified; say "spoof-resistant".
2. **No purchase language in the apps, ever.** The CI store-compliance job enforces it.
   The free-tier cap shows a neutral "list full", never an upsell.
3. **Production refuses to start when misconfigured.** It requires a stable signing key,
   Postgres, a Stripe webhook secret, dev endpoints switched off, and https CORS
   (`config.validate_for_runtime`).
4. **Activation is rate-limited hard** (8/min per IP plus a global 240/min breaker),
   because codes are only 6 digits and the payload contains personal data. The limiter
   runs in-process by default, or shared across instances when `REDIS_URL` is set. The
   global breaker logs `ACTIVATION GLOBAL RATE LIMIT TRIPPED`; alert on that line.
5. **Caregiver API keys are stored as hashes** (SHA-256). The plaintext is shown once.
6. **Alembic owns the production schema.** `create_all` runs only in dev/test. CI runs
   `alembic upgrade head` and `alembic check`, so a model change without a migration fails.
7. **iOS project format is pinned to XcodeGen 2.42.0** (objectVersion 56). Homebrew's
   newer XcodeGen writes format 77, which the CI runner's Xcode 15.4 can't open.
8. **Dev builds talk to a local backend.** iOS Debug uses `http://localhost:8000`; Android
   debug uses `http://10.0.2.2:8000` (the emulator's name for the host machine).
   Plain-HTTP exceptions are limited to those local hosts.
9. **Android `allowBackup=false`**, so cached contacts aren't copied off the device.

## 5. Bugs found and fixed this session (useful context)

- iOS CI: newer XcodeGen wrote a project Xcode 15.4 couldn't open. Fixed by pinning 2.42.0.
- Activation login failed on device: the app expected `publicKeyBase64`, but Swift's
  snake-case conversion turns `public_key_b64` into `publicKeyB64`. Fixed, with a
  regression test.
- Signature mismatch: Pydantic serialized `issued_at` with `Z` while the backend signed
  `+00:00`. Fixed by signing the exact string that is sent.
- A stale dev SQLite database returned 500 errors after model changes. This is why
  Alembic was adopted.
- Android first compile: `item` was imported, but it is a member of `LazyGridScope`, not
  a top-level function. Removed the import.
- **Apple's number was wrong:** `1-800-275-2753` corrected to `1-800-275-2273`
  (1-800-APL-CARE).
- **AT&T tile contrast was too low** (2.74:1, fails WCAG). Switched to black text (7.68:1).

## 6. How to run and test

```bash
# data
python data/validate.py
python scripts/check_store_compliance.py

# backend (29 tests)
cd backend && pip install -r requirements.txt && python -m pytest -q
uvicorn app.main:app --port 8000
curl -s -X POST 'http://localhost:8000/v1/dev/accounts?senior_display_name=Mom'  # get a code

# web: funnel + dashboard (simulated checkout when STRIPE_API_KEY is unset)
cd web && python -m http.server 5173   # open /, /dashboard.html

# iOS (macOS): cd ios && ./bootstrap.sh
# Android:     cd android && gradle :app:assembleDebug :app:testDebugUnitTest
```

There is no mobile toolchain in the cloud sandbox, so the apps have only been compiled
and unit-tested in CI. **Nobody has run either app on a physical device yet.**

## 7. Environment gotchas

- Official brand websites block automated requests from this sandbox (HTTP 403 for both
  WebFetch and curl). That is why number checks were web-search based. Run
  `verify_numbers.py` from a normal network.
- Use the GitHub MCP tools for GitHub; the `gh` CLI isn't available in this sandbox.
- Run `pytest` from `backend/`. If you work on a dev SQLite file after a model change,
  delete `backend/senior_directory.db` first.
